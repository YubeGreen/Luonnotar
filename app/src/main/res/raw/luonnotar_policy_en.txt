Luonnotar Terms of Use and Privacy Notice

Policy version: 1.3
Effective date: July 24, 2026

Welcome to Luonnotar. Please read this policy in full before using the app. Luonnotar is a local, VPN-dependent connectivity guardian and diagnostic tool for Android devices. It observes Proton VPN, the default network, Wi-Fi, the foreground guardian service, system scheduling, and the FCM environment to help diagnose connectivity and message-delivery reliability after the screen is locked.

By continuing to use this app, you confirm that you have read, understood, and agreed to the following.

GPT-5.6 Sol is responsible for generating the project code, interface, documentation, and technical implementation. YubeGreen is responsible for defining requirements, testing, operation, deployment, acceptance, and final usage decisions. Although the app has been built, tested, and manually reviewed, it may still contain software defects, device-compatibility issues, incorrect judgments, or unexpected behavior. Users should independently verify diagnostic conclusions.

2. Purpose and capability boundaries

Luonnotar is used to:

Maintain a foreground guardian service explicitly enabled by the user;
By default, hold a CPU WakeLock only briefly when required for a task, and release it when the task finishes;
Allow the user to manually enable "Screen-off CPU Guard" on any supported vendor device; this keeps a CPU WakeLock only while the guardian is active and the screen is off, and releases it when the screen turns on or the guardian is paused or stopped; it does not automatically enable a high-performance Wi-Fi lock;
Allow permanent all-day CPU Lock, high-performance Wi-Fi, screen-event probing, and high-frequency network probing only when individually enabled by the user in Lab mode;
Record changes to the default network, internet validation, and VPN networks;
Check whether Google Play Services is present and the FCM environment state visible to this app;
Run low-frequency HTTPS connectivity checks while the VPN is available;
Record startup, network switching, VPN switching, recovery actions, and system scheduling evidence;
Generate diagnostic files for the user to inspect and share manually.

Luonnotar is not a VPN. It does not establish a Proton tunnel, control private WhatsApp, GMS, or Proton connections, forge Google FCM traffic, or directly connect to Google's private FCM socket. A normal APK cannot silently enable system Always-on VPN or Lockdown and cannot guarantee that third-party processes will never be terminated by the system. In split-tunnel scenarios, "Block connections without VPN" may be disabled, but the user must independently confirm that targets such as WhatsApp and GMS have not been excluded from Proton.

Android 12 and later normally prevent apps from starting a foreground service directly from the background. Luonnotar only attempts automatic recovery when a system exemption is available, such as an exact alarm requested by the user. When an inexact alarm fires, the user will normally need to tap the recovery notification. Doze also limits the frequency of allow-while-idle alarms. Luonnotar therefore does not promise recovery within one minute and does not promise guaranteed automatic resurrection after the service has actually been killed by the system.

3. Local operation and network access

Configuration, state, and logs are primarily stored locally on the device. The app requests the INTERNET permission only for VPN-dependent connectivity checks after the user enables the guardian and for normal Android/Google component networking. If the VPN is lost, Luonnotar stops its own network probes.

The app does not provide developer-operated accounts, advertising, commercial tracking, or an automatic diagnostic-upload service. Unless the user explicitly exports files through the system share interface, Luonnotar does not automatically send logs to the developer or to third parties.

4. Information that may be recorded

Depending on the Android version, device vendor, and user configuration, the app may record:

Date, time, time zone, device uptime, and boot ID;
Device model, system version, app version, and process state;
Wi-Fi, cellular network, default network, internet-validation, and VPN state;
VPN app package name and ADB-verified summaries of Always-on, Lockdown, and bypassability state;
Battery, charging, screen, CPU/Wi-Fi lock, and system scheduling state;
Guardian-service heartbeat, PID, rebuild generation, timer drift, and recovery reason;
Whether Google Play Services exists and token-timing information visible to this app;
HTTPS probe latency, failure counts, error types, and Luonnotar's own logs.

Only after the user explicitly acknowledges the privacy notice and grants Notification Access in system settings may the optional notification-arrival verification mode record the WhatsApp/GMS package name, Android notification postTime, the time Luonnotar observed the event, and a truncated SHA-256 hash of the notification key. This mode does not store notification body text, contacts, group names, or chat content. It records Android notification-delivery events and is not equivalent to directly reading a private FCM socket.

Diagnostic data may indirectly contain package names, network addresses, device identifiers, file paths, or error information. Users should inspect diagnostic files for sensitive content before sharing them.

5. Permissions and ADB

Notification permission is used to display foreground guardian state. Network, Wi-Fi, WakeLock, foreground-service, boot-broadcast, and exact-alarm permissions are used to implement the user-enabled extreme keepalive and recovery scheduling. Notification Access is used only for the optional notification-arrival verification mode. Revoking Notification Access does not affect CPU/Wi-Fi locks, VPN monitoring, or HTTPS keepalive.

Some system-level VPN evidence is read by the user in an authorized ADB session and then written as a summary through a receiver protected by android.permission.DUMP. Ordinary third-party applications cannot call this entry point. Luonnotar does not bypass Android's permission model and does not treat ADB verification as permanent truth; records are evaluated by boot cycle and validity period.

6. Background operation and device impact

Extreme Keepalive may continuously display a foreground-service notification and may increase battery use, memory use, Wi-Fi active time, system scheduling activity, and device heat. The app avoids unlimited high-frequency polling, but it cannot guarantee continuous survival on every vendor system and cannot guarantee that FCM or WhatsApp messages will always arrive immediately.

The user can stop the guardian service from the main interface. Force stop, revoked permissions, system updates, device reboot, vendor background cleanup, or storage faults may interrupt functionality.

7. Diagnostic results and limitation of responsibility

Descriptions such as "healthy", "verified", "abnormal", "disconnected", or similar labels are technical evidence summaries, not absolute conclusions. VALIDATED only means Android considers the network capable of usable internet access; it does not prove that the FCM or WhatsApp long-lived connection is intact. When the app cannot read a third party's FCM token, private socket, or message-send time, it does not fabricate that evidence.

No guarantee is made for data loss, connectivity interruption, missed notifications, additional traffic, battery consumption, device abnormality, or other indirect loss arising from use, misuse, reliance on, or inability to use the app.
